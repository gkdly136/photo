# 产品设计：从「长时间对准背景」到可执行的指导

0.2 的实际门控、建议能力和模型训练路线以 [辅助逻辑说明](ASSISTANCE_LOGIC.md) 为准。默认停留 2.5 秒，容忍轻微手抖，并提供「立即辅助」。

## 目标用户与核心价值

业余摄影爱好者不一定能把「照片不够好看」转换成下一步操作。产品优先给出一个能马上尝试的动作：换人物落点、转一点身体、观察亮部或比较机位，再由用户决定。

第一版选择手机原生相机闭环，先验证「看见提示 → 能照着做 → 比较照片」是否有效。手机镜头稳定并不证明用户一定想拍照，因此提供停留时长和「重新观察」，所有建议保持可忽略。

## 实时处理流程

1. CameraX 将预览和分析绑定到 Activity 生命周期，后台停止取景。
2. 每秒最多约 5 帧进入分析，采用保留最新帧策略；分析尺寸以 640×480 为首选，实际由设备协商。
3. 从亮度平面稀疏采样，获得明暗分布；根据相邻帧与稳定起点比较判断移动，陀螺仪补充旋转信息。
4. 人像模式启用 bundled ML Kit 人脸和人体姿态模型。CameraX 的 MlKitAnalyzer 负责将结果变换到 PreviewView 坐标，包括旋转、裁切和前置镜像。
5. 达到停留时长后，规则引擎根据当前模式、构图选择、用户选择的拍摄氛围和观测生成建议。
6. 确认持续移动或明显换景时清除旧建议，重新累计停留时间；检测到人员的建议以约 1.2 秒以上的间隔更新，降低文字跳动。
7. 拍照写入系统 MediaStore，不保存连续分析帧。

## 建议的三个层次

| 类型 | 示例 | 用户看到的依据 |
| --- | --- | --- |
| 测量 | 预览亮区较多 | 采样占比，不宣称 RAW 已过曝 |
| 模型估计 | 最大人脸偏右、手腕低于髋部 | 人脸/关键点的二维结果和置信度限制 |
| 创作方案 | 安静地望向远处、前景增加层次 | 用户选择或摄影原则，不伪装为检测结论 |

每条规则需包含：触发条件、指令、证据说明、来源 ID。首版源码中的证据文字同时承担产品解释功能。

## 分阶段迭代

### 0.1：本仓库实现

原生实时取景、稳定触发、人脸与姿态、亮度检查、可选构图模板、人工水平线、原片保存、来源追溯、合成演示和自动构建。

### 0.2：摄影理解

在真实拍摄测试集上验证地平线、天空/地面分割、主体显著性、背景杂物和人头后方直线干扰；补充人物手动选择。对每个模型添加置信度阈值、无法判断的出口和不同焦距下的评测，不仅按获奖照片相似度排序。

### 0.3：情境化方案

经过授权建立教材/作品索引，用检索增强的多模态分析提出 2–3 套可比较的拍摄方向。保留端侧稳定与几何检查；若启用云端，单独告知并由用户明确选择上传。不要把付费书籍或获奖图片的公开可见误当成可训练许可。

### 0.4：外接相机

先选定相机品牌、型号和连接方式，再验证厂商 SDK 的实时流、旋转、延迟与拍照控制。手机画面建议不能自动证明适用于不同焦距的独立相机。

## 成功标准

- 在支持设备中，从稳定取景到首条建议的延迟应接近所选停留时间加一个分析周期与推理耗时；需实测记录 P50 / P95。
- 盲测时用户能准确说明建议让「人物」还是「相机」向哪边移动。
- 对同一场景随机使用/不使用建议，比较用户偏好、完成时间和放弃率。
- 记录误触发、低光失效、多人选择错误、坐标偏移和温升。首版未承诺量化准确率或最低帧率。
