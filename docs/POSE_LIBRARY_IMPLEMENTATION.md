# 0.3 原创姿势库与手臂对照

本轮实现 40 个原创动作示意：12 个站姿、12 个坐姿、8 个靠姿、8 个轻动作。所有线稿由本项目手写二维几何在 Android Canvas 绘制；没有打包、描摹或提取第三方姿势图库图片。原图库仅用于研究分类与浏览方式，下载和用途限制见[接入方案](POSE_LIBRARY_PLAN.md)。

## 使用方式

人像取景上方提供「姿势库 · 40」。选择站姿、坐姿、靠姿或轻动作，选择全身或半身、正面或斜侧，并确认是否有稳固座椅、可轻靠墙面。坐姿与靠姿缺少对应条件时不提供候选。支持在本机收藏。

稳定取景后，「姿势」类别提供三个候选和「换一组参考」。选择候选或在姿势库查看动作、构图、目光与表达、光线说明后，点击「选为本次目标」。已选目标会保持，人物摆动作不会自动替换姿势。设置中可打开「目标手臂虚线」；暖色实线是可选的当前骨架，蓝色虚线是有可靠对照时的参考手臂。

清除目标、真实换景、切换模式或镜头、切后台和 Activity 重建会撤回本次目标；拍摄条件使目标不再适用时也会清除。收藏只存动作编号，不存相机照片。拍摄原片继续不包含辅助线。

## 实时对照的范围

沿用预训练 ML Kit 和每秒最多约 5 次的相机分析。本轮没有训练模型或新增云端 API。只有当前会话的新画面、单张可见人脸、与用户选择基本兼容的头向，以及双肩、双髋、双肘和双腕均可用时，才对照手臂。

线稿提供的是原创示意目标，未经真实摄影标定。匹配先修正预览宽高比，再消除平移与尺度差异；保留身体倾斜，使用肩部左右顺序处理镜像。仅比较手腕和手肘相对躯干的位置，不评价体型、容貌、美观或真实心理，不判断腿部、手指、重心和三维距离。线稿的正面与斜侧只是二维示意，不能作为标定机位。

0.65 仍是入画可能性筛选初值，不是定位准确率。关节有缺失、坐标异常、身体过小、侧面过窄、目标超出取景、多人、背身或检测故障时，只提供参考。身后遮挡手部和轻动作全部只作示范，不自动纠正。

连续至少三个不同时间的新帧、持续至少 400 ms 得到相同提示后，才显示测量提示；相邻有效采样不能间隔超过 450 ms。切换提示至少间隔 1.2 秒。新动作与旧提示不一致时先显示观察状态，避免继续显示「已接近参考」；证据失效则立即撤回提示和目标骨架。超过 900 ms 的观察不用于纠正。这些是工程初值，尚未在红米 K80 标定。

## 帧与会话隔离

`CameraSession` 按相机帧时间戳为一次委托检测保留采样时间、视口尺寸及会话版本，通过 [MlKitAnalyzer.Result.getTimestamp](https://developer.android.com/reference/androidx/camera/mlkit/vision/MlKitAnalyzer.Result#getTimestamp()) 找到对应记录，不读取可被下一帧覆盖的「最新记录」。换景与重置增加版本并清空记录，迟到检测和亮度结果不能覆盖当前画面；视口尺寸变化也会丢弃旧结果。`PoseSession` 单独管理选择版本、主角跟踪编号、提示的连续帧与冷却。只有姿态匹配自身的状态变化，不重置背景稳定门控。

多人场景不把 SDK 的单人骨架分给最大人脸。已观察到的单人跟踪编号改变时清除目标；没有可靠编号时不声称已验证人物身份，用户换主角应重新选择或重新观察。

## 数据与后续工作

动作库代码在 `core/PoseLibrary.kt`，匹配与会话在 `core/PoseSession.kt`，姿势库界面与原创线稿在 `app/PoseLibraryDialog.kt`、`app/PoseSketchView.kt`。不把示意坐标当作真实摄影标注或训练真值。

现有视频点评库仍为本地、待逐条审核的候选数据，未自动并入本版规则或模型。下一步需要在自有摄影样本上复核动作可执行性、提示容差与视觉表达，再依据主动提供的采纳反馈评估是否需要训练推荐排序器。

本轮增加核心测试覆盖条件筛选、镜像、宽高比、缺失点、旧帧、多人、主角变化、锁定、连续帧与冷却；增加模拟器用例覆盖浏览、选定、重建撤回、座椅条件和收藏。实际通过情况与安装包以[验证记录](VERIFICATION.md)为准，不把测试用例存在当作测试通过。
